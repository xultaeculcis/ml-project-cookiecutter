# Glossary

> The shared vocabulary of this project: one name for each concept, with one definition. Use these terms exactly in
> code, docs and messages. When the meaning of a term changes, change it here first.

## Rules

- Use one word for each concept. If there are other words for the same concept, list them under _Avoid_.
- Keep definitions short: one or two sentences. Say what the term is, not what it does.
- Add only project-specific terms. General programming terms do not go here.
- Model targets and class names are terms. Their definition must match the labeling rules. Say where the labeling
    rules are.
- Keep the terms in alphabetical order. Add subheadings when groups of terms appear.
